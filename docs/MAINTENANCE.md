# Maintenance and governance

## Release policy

Use semantic catalog versions:

- Patch: wording, glob, detection, or non-material clarification.
- Minor: new module, new secure default, or expanded coverage that should be reviewed by adopters.
- Major: meaningfully stronger requirements, output-format changes, removed modules, or generator behavior requiring migration.

Tag releases used by onboarding automation. Generated state records the catalog version, but repositories should also pin the Skills Hub release in their automation.

## Review cadence

- Quarterly: GitHub Copilot format/surface support, false-positive feedback, dependencies/reference links, framework security defaults.
- At least annually: every module's security content and normative strength.
- Event-driven: major OWASP/NIST/company-policy update, new platform rollout, material incident, common code-review finding, or deprecated API/default.

Update `lastReviewed` in `catalog/catalog.json` only after the full catalog review. For a targeted module change, record the review in the pull request/release notes until per-module dates are added to the schema.

## Change approval

Material instruction changes should have:

- A security reviewer for correctness and threat coverage.
- A developer/platform reviewer for feasibility and noise.
- A representative generated-output diff in both modes.
- Passing catalog validation and tests.
- A rollout note when `MUST` strength or detection scope changes.

## Useful adoption metrics

- Repositories generated by mode/preset and catalog version.
- Modules most frequently excluded or manually modified.
- Developer-reported false positives and unnecessary churn.
- Security findings that repeat despite an applicable instruction.
- Defects prevented during coding or caught by the developer before PR.
- Generation drift and instruction-removal attempts.

Do not use suggestion acceptance rate as a security-success metric by itself. A useful instruction may cause Copilot to avoid proposing an unsafe pattern rather than produce an observable accepted suggestion.
